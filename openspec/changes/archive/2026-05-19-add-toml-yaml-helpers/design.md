## Context

The `{{json}}` helper (`src/templates/helpers.rs:33-53`) serializes any `serde_json::Value` to compact JSON and writes it to the Handlebars output. TOML-based providers (Codex, Mistral Vibe) currently use manual `{{#each}}` loops to build TOML syntax, which is error-prone and doesn't handle edge cases like special characters in values.

Both `toml` (0.9.8) and `serde_yaml` (0.9.34) are already in `Cargo.toml`. The `toml` crate's `to_string` function only works on objects (tables) — it returns `UnsupportedType` for primitives and arrays.

## Goals / Non-Goals

**Goals:**
- Add `{{toml}}`, `{{toml-inline}}`, and `{{yaml}}` helpers that mirror the `{{json}}` helper pattern
- Simplify mistral-vibe and codex MCP templates by replacing manual `{{#each}}` loops
- Make all three helpers available globally so user custom templates can use them too

**Non-Goals:**
- No changes to the registry fetch/cache pipeline
- No changes to how templates are resolved or rendered beyond helper registration
- No YAML provider template updates (no current provider uses YAML)

## Decisions

### Two TOML helpers instead of one with a mode flag

Handlebars helpers receive positional params, not named arguments. `{{toml "inline" value}}` would treat `"inline"` as the value. Two separate helpers (`{{toml}}` and `{{toml-inline}}`) is the cleanest approach.

### `{{toml}}` outputs bare key-value lines (table style)

`toml::to_string` on `{"KEY": "val"}` produces `KEY = "val"\n`. This matches the codex template pattern where content is written inside a `[section]` block.

### `{{toml-inline}}` wraps output in `{ ... }`

`toml::to_string` doesn't produce inline table syntax. The helper will serialize to TOML, then wrap the result: `{ KEY = "val", FOO = "bar" }`. This matches the mistral-vibe `env = { ... }` pattern.

### `{{yaml}}` uses block style

`serde_yaml::to_string` produces block-style YAML by default. This is the most readable format and matches how YAML config files are typically written.

### Error handling for non-object values

`{{toml}}` and `{{toml-inline}}` will return a render error if passed a non-object value (string, array, number, null), since TOML requires key-value pairs at the root. The error message will indicate that only objects are supported. `{{yaml}}` accepts any value since YAML supports bare scalars, sequences, and mappings.

## Risks / Trade-offs

| Risk | Mitigation |
|------|-----------|
| `toml::to_string` may produce different output across versions | Pin `toml` crate version; add unit tests that assert exact output |
| Inline table wrapping with `{ ... }` may not handle nested objects correctly | Test with nested structures; if needed, use a different serialization approach |
| Template checksums in `registry.json` will be stale after updating `.hbs` files | `registry.json` is auto-generated by CI — no manual update needed |
